# DynaDFlash

This repository contains the training and evaluation code used for the DynaDFlash research project!

# Models

DFlash takes hidden states from layers 2, 10, 18, 26, and 34 of the target model, concatenates them, and projects them into the draft model.

Our modification keeps the same projection as DFlash but adds a linear gate before it. The gate takes the hidden state from layer 34 and computes five weights, one for each of the selected target layers. Each hidden state is multiplied by its corresponding weight before concatenation and projection.

The gate introduces only 20,480 additional parameters.

The trained [DFlash baseline](https://huggingface.co/midas-llm-research/qwen3-8b-dflash-baseline) and [DynaDFlash](https://huggingface.co/midas-llm-research/qwen3-8b-dynadflash) models are on Hugging Face.

# Evaluation

We train both models using a frozen Qwen3-8B target and the same 792,000 training examples in the same order. Both use DFlash's original training methodology with a block size of 16.

Training runs for one epoch, consisting of 24,750 updates with a global batch size of 32 on two H100 GPUs. We use 990 warmup steps, a peak learning rate of $6\times10^{-4}$, and cosine learning rate decay. We evaluate the final checkpoints after checking their training histories.

After observing stronger performance on math prompts, we conduct a separate test using 700 held-out prompts from MetaMathQA and Orca-Math. Of these, 647 come from MetaMathQA and 53 from Orca-Math.

For each prompt, we provide the question without its answer. The target model generates the first token, and the draft model predicts the next 15 tokens. We then measure how many tokens match the target model's greedy predictions, including the first token generated by the target. We count acceptances from the beginning of the draft and stop at the first mismatch.

We also measure decoding throughput using SGLang 0.5.18 on one A100 GPU. We select 24 fixed MetaMathQA prompts and generate 64 tokens per request using greedy decoding.

We test both models with eight concurrent requests. Each experiment is repeated three times using new servers, alternating the order in which the models are tested. Throughput is measured in output tokens per second.

# Results

Mean accepted tokens on 700 math prompts.

| Model | Accepted tokens | Change |
| --- | ---: | ---: |
| DFlash | 2.98 | -- |
| DynaDFlash | **3.13** | **+5.0%** |

On the 700 math prompts, the dynamic model achieves a mean accepted length of 3.13 tokens, compared to 2.98 for the original DFlash model. This is an improvement of about 5%, or 0.15 additional tokens per prompt.

The 95% confidence interval for the difference is 0.07 to 0.22 tokens, with $p<0.001$.

Most of this improvement comes from the 647 MetaMathQA prompts, where the dynamic model accepts an additional 0.16 tokens on average. We do not observe an improvement on the smaller set of 53 Orca-Math prompts.

The results are different on our full evaluation, where the original DFlash model and the dynamic model have no statistically significant difference in acceptance length. This suggests that the benefits of dynamic weighting may depend on the type of input rather than improving drafting across all tasks.

Throughput is measured in output tokens per second.

| Model | Output tokens/s | Change |
| --- | ---: | ---: |
| Autoregressive Qwen3-8B | 655.4 | -- |
| DFlash | 965.0 | -- |
| DynaDFlash | 1004.5 | +4.1% |

# Discussion

A key limitation is that both models were trained independently and do not match the acceptance length of the published DFlash model by z-lab. This makes the observed improvement in acceptance length less reliable as both models fall below the acceptance length of other DFlash drafters.
